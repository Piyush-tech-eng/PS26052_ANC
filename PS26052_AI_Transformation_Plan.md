## 2. Mandatory fixes to Module 7 before touching AI (carried over from the prior audit — do these first, they're small and they'd otherwise silently corrupt every AI result downstream)

1. **Seed-pairing bug**: `_signal()` is called with `definition.seed`, and `build_scenario_matrix()` increments the seed once per Cartesian-product entry *including controller*. So `none` / `fxlms` / `fxnlms` for the "same" scenario currently run on three *different* random noise instances. Fix: derive the reference-signal seed from everything **except** controller, so all controllers for one scenario replay the identical disturbance.
2. **Split-leakage bug**: `split_dataset()` groups by `run_id` (`scenario_id + controller`). Fix: group by the pre-controller scenario key instead, so controller variants of one scenario stay in one split — this is literally the rule your own project docs already state ("controller variants derived from the same underlying disturbance realization should generally remain within the same high-level split").
3. **Minor**: relativize the hard-coded Windows path baked into `dataset_manifest.json`; add `experiments/` to `pyproject.toml`'s `pythonpath` so all 33 test files collect without a manual override.

These are surgical patches to `src/anc/evaluation/scenarios.py` and `dataset.py` — not rewrites. Do them before Section 3, because the speech pipeline will reuse `split_dataset()`'s grouping logic.

## 3. Extend Module 7 into the PS26052 dataset contract (this is the part of the draft proposal I'm keeping, tightened against what's actually implementable)

### 3.1 New source-identity objects (add to `src/anc/scenarios/` or a new `src/anc/speech/` package — don't touch M1–M6)

```
SpeechSample:  audio, sampling_rate, source_id, speaker_id, duration, provenance, license
NoiseSample:   audio, sampling_rate, noise_id, noise_family, source_id, duration, provenance
```

`noise_family` taxonomy, matching the PS statement directly: `impulsive` (gunshot/artillery), `rotor` (helicopter/drone), `engine_vehicle`, `broadband`, `colored`, `wind`, `alarm_siren`.

### 3.2 Where to actually get the audio (the plan can't be "general" without naming real, obtainable sources)

You do not need to record anything to get started — public, license-clear corpora cover every category in the PS statement:

- **Clean speech**: LibriSpeech (train-clean-100/360) or VCTK — both are standard, high-quality, multi-speaker, freely available, and are what most published ANC/speech-enhancement papers benchmark against, so results are comparable.
- **General/environmental noise**: MUSAN (speech/noise/music) and ESC-50 / FSD50K for wind, sirens, engines, alarms.
- **Defence-specific noise (gunshots, artillery, rotor)**: purpose-built gun/impulsive-sound datasets and freesound.org query-based collection (engine, rotor, siren categories exist there under CC licenses) — flag these explicitly in `provenance` since license terms vary per clip.
- Until real defence-audio access is secured, **synthetically approximate** rotor/engine/impulsive noise using signal models you already have infrastructure for (M1's burst/impulse generator for gunfire-like transients, colored-noise generator with rotor-harmonic tonal components for helicopter-like noise) — tag these `provenance.synthetic_approximation = true` so they're never confused with real recordings later. This lets you start training immediately while real-audio sourcing runs in parallel.

### 3.3 Controlled-SNR mixing (new, small, deterministic module: `src/anc/speech/mixing.py`)

```
m[n] = s[n] + alpha * v[n]        # alpha computed to hit a target SNR
```

Store `s[n]`, `v[n]`, `m[n]`, and the exact `{snr_db, alpha, speech_source_id, noise_source_id, noise_family}` config — this is what makes a training sample reproducible and auditable, matching the discipline already used for `ScenarioDefinition`.

Initial SNR ladder (configurable, not hardcoded): `{-5, 0, 5, 10, 15}` dB, extendable once the PS target (>15 dB output SNR) is being approached, so the model sees both very hard and near-target-quality inputs.

### 3.4 Scenario matrix upgrade

Extend `build_scenario_matrix()` (currently `signal_class × input_level × path_condition × source_type × secondary_path_model × controller`) with two new axes: `speech_id × noise_family × snr_db`, reusing the exact same `ScenarioDefinition` dataclass and `run_scenario()` execution path — **this is the "extend, don't rebuild" move**: the classical FxLMS/FxNLMS replay code doesn't change at all, it just now receives `m[n]` as its reference/measured input pair instead of synthetic broadband/tonal signals.

### 3.5 New mandatory window fields (extends `DatasetWindow`, doesn't replace it)

```
reference_x            (already exists)
noisy_speech            m[n]           <- NEW
baseline_residual       e_ANC[n]       (already exists, from classical FxLMS/FxNLMS)
clean_speech_target     s[n]           <- NEW, THE missing supervised target
noise_component         v[n]           <- NEW, optional
controller_output_y     (already exists)
filtered_reference      (already exists)
```

`target_available` flips to `True` for every speech scenario window — this is the single field that turns the dataset from "ANC benchmark" into "supervised speech-enhancement dataset."

### 3.6 Augmentation: keep it as two separate layers (this part of the draft proposal is correct and worth keeping exactly as stated)

- **Dataset-level (Module 7, deterministic, saved)**: fixed noise-mixing variants, reverberation, clipping — these become part of the frozen, versioned dataset so results are reproducible.
- **Training-time (Module 8, random, on-the-fly)**: standard random augmentation during training. Keep this out of Module 7 entirely so Module 7 stays framework-agnostic (no PyTorch/TensorFlow dependency in the dataset-prep code).

### 3.7 Splitting rule (tightened from the draft, using the actual bug-fixed `split_dataset()` from Section 2)

Split by **speaker/source identity first**, before any windowing:
```
speech speaker/utterance identity + noise source identity + scenario realization → split assignment → window extraction
```
Concretely: extend the same-scenario grouping key already fixed in Section 2 to include `speech_source_id` — never let the same speaker or the same noise recording appear in more than one split. This is a direct application of your existing `split_dataset()` design, just with a richer key.

### 3.8 Directory layout — keep the existing `m7_01_scenario_matrix_evaluation` output structure, add a sibling package rather than replacing it

## 4. Module 8 — the AI model (new package `src/anc/ai/` or `src/ai/`, kept fully separate from `src/anc/`)

### 4.1 What to actually build, matching the PS statement's explicit allowances

The PS statement explicitly allows either time-frequency or raw-waveform models, sub-band or full-band, complex-domain phase handling. Given the real-time + edge-deployment requirement (Jetson-class hardware, low latency) stated later in the same PS, the pragmatic path is:

**Recommended primary architecture: a lightweight time-domain, causal, complex-spectral-mapping model in the DTLN / RNNoise / GRU-TasNet family** — small enough for real-time embedded inference, proven for exactly this SNR/STOI/PESQ target range in published work, and it accepts the `[x_i, e_i]` (or `[x_i, e_i, m_i]`) multi-channel input your Module 7 dataset will already produce.

**Input**: `X_i = [reference_x, baseline_residual]` (the skill's own recommended default, shape `(2, L)`) — extend to `[reference_x, baseline_residual, noisy_speech]` as an optional 3rd channel once the speech pipeline is live, since the classical residual already does part of the job and the model should learn the remainder, not re-derive everything from raw mixture alone.

**Target**: `clean_speech_target` (`s_i`).

**Two-stage learning framing, matching your own hybrid philosophy already stated in the Master History**: classical ANC/FxNLMS removes the reference-correlated portion first; the AI model's job is explicitly framed as *residual* speech-preserving denoising, not "replace the whole pipeline." This is architecturally cheaper to train (smaller correction, not full separation) and matches "AI adds value on top of a validated baseline" rather than competing with it.

**Secondary/comparison architecture** (for the benchmark matrix in Section 8, not for initial deployment): a small Conv-TasNet-style or complex spectral-mapping (STFT + complex ratio mask) model, to demonstrate the time-frequency alternative explicitly required by the PS statement's "either/or" phrasing.

### 4.2 Losses (directly per PS statement)

- Primary: **SI-SNR** (scale-invariant, standard for speech separation/enhancement, directly optimizes the SNR metric the PS targets).
- Auxiliary: **L1/L2 time-domain loss** for waveform stability, plus a **perceptual loss term** (e.g., multi-resolution STFT loss) to help PESQ/STOI without needing a differentiable PESQ surrogate.
- Keep the loss composition configurable (weighted sum) so the acceptance-gate benchmark in Section 8 can report which loss combination hits which metric best — this is exactly the "show where each approach succeeds or fails" philosophy your Master History already commits to.

### 4.3 Evaluation metrics (extend `src/anc/evaluation/metrics.py`, don't fork it)

Add `compute_stoi`, `compute_pesq`, `compute_si_snr` as new functions in the same module, following the exact same "pure function on numpy arrays, no side effects" pattern already used by `compute_noise_reduction_db` etc. `evaluate_scenario()` gets extended (backward compatible — new optional fields) to report these whenever a `target` is present, so both the classical-ANC scenarios (no target) and speech scenarios (target present) run through one evaluation function.

## 5. Training pipeline (net-new, lives outside `src/anc/` entirely — e.g. `src/ai_training/`)

```
load_dataset("results/m7_speech_ai_handoff")   # existing loader, extended
    → apply frozen normalization (train stats only — this is currently computed but never applied anywhere in the repo; implement `apply_normalization()` here)
    → training-time augmentation (Section 3.6, random)
    → model forward pass → SI-SNR + L1 + perceptual loss
    → validation each epoch on the validation split (STOI/PESQ/SNR, no gradient)
    → checkpoint on best validation STOI (not just loss — perceptual quality is the PS's actual target)
    → final held-out test-split report: SNR, STOI, PESQ, per-noise-family breakdown
```

This is intentionally the one place where a specific ML framework (PyTorch, matching the PS statement's later mention of ONNX/TensorRT export) gets introduced — keeping it fully outside `src/anc/` preserves the "AI preparation separate from classical ANC execution" rule already in your project philosophy.

## 6. Module 9 — Hybrid integration + real-time inference engine

- Wrap the trained model + the existing `run_anc_replay()` FxNLMS path behind one streaming-capable interface: chunked audio in → classical ANC residual computed causally → AI model consumes a fixed-size buffer of `[x, e]` → enhanced speech chunk out.
- Chunk size becomes a first-class parameter (trades latency vs. context), reusing the existing `WindowConfig` concept from Module 7 rather than inventing a new one.

## 7. Module 10/11 — Robustness, streaming, and edge deployment

- Robustness matrix: stationary / nonstationary / impulsive / mixed speech+noise, reusing the same `ScenarioDefinition`-based matrix machinery already built in M7 — no new scenario infrastructure needed, just more axis values.
- Export path: PyTorch → ONNX → TensorRT (matches the PS statement's named target, Jetson AGX Orin class hardware) with FP16/INT8 quantization comparisons.
- Benchmark on-device: latency, real-time factor, CPU/GPU utilization, memory, and — critically — confirm SNR/STOI/PESQ don't regress after quantization (a very common failure mode; must be measured, not assumed).
